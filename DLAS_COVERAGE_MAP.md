## The single biggest structural gap

Almost every rule module in `lib/case/` (`audit.ts`'s `decideSend`/`assistVerdict`/`sensitiveOpenNotice`, and the `mediations`/`transfers`/`tranches`/`settlements` tables) is written carefully and covered by `scripts/test-case-rules.ts` — but is **never called from a single route or component**. The logic a judge would want to see is already correct; it just isn't wired to a screen yet. Wiring these five things would move 5 of the 8 lowest-scoring rows up at least one level:

1. Call `decideSend()` before every SMS/voice send (A1, A3)
2. Call `sensitiveOpenNotice()` from the case-detail "open" action (A3, A1)
3. Write to `assist_decisions` when a DLAO accepts/overrides a recommendation (B1, T8)
4. Give the lawyer a button that sets `lawyer_action_log.done_at` (A5, B5, T1)
5. Build one referral screen against the existing `transfers` table (A3, B6, T2)
